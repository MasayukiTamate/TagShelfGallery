# 画像管理アプリ設計プロンプト

## 目的
理想の画像管理アプリを設計し、画像ファイルを「タグ」で整理・検索・整理・閲覧できるようにする。ユーザーは大量の画像をすぐに見つけ、整理し、再利用できる体験を得る。

## 方向性
本アプリは単なる画像ビューアではなく、以下を満たす「タグ中心の画像ライブラリ管理アプリ」として設計する。

- 画像ファイルをタグで分類できる
- フォルダ構造に依存しない整理ができる
- 似た画像や関連画像を一目で見つけられる
- ラベル付け、評価、検索、並び替えを一貫して扱える
- 画像の移動や自動整理が簡単にできる
- 既存のローカル画像フォルダを活かしつつ、メタデータ管理を強化する

## 目標ユーザー
- 画像を大量に持っている人
- 作品、写真、素材、参考資料を整理したい人
- 画像をカテゴリごとに管理したいが、フォルダ分けだけでは不足している人
- 似た画像をまとめて検索したい人

## 基本機能

### 1. 画像表示
- 画像一覧をサムネイル表示する
- 1枚表示・スライド表示・全画面表示に切り替え可能
- WebP, JPG, PNG, GIF など主要形式をサポートする
- 画像の回転、拡大縮小、比較表示が可能である

### 2. タグ管理
- 画像に自由タグを付与できる
- 一つの画像に複数タグを設定できる
- タグの作成、編集、削除を行える
- タグごとに画像一覧をフィルタできる
- 複数タグの AND / OR / 除外検索が可能
- よく使うタグを「お気に入りタグ」や「使用頻度順」で管理できる

### 3. ファイル整理
- タグで画像の整理ができる
- タグに応じて画像を移動・コピーできる
- 画像を「未分類」「候補」「採用」「捨てる」などの状態管理ができる
- バッチ処理で複数画像へ一括タグ付けができる
- タグの自動候補提案ができる

### 4. 検索と発見
- 名前検索
- タグ検索
- 日付検索
- 評価順検索
- 類似画像検索
- 類似タグ検索
- 画像の中身や色相に基づく簡易類似検索（将来拡張）

### 5. 評価と状態管理
- 画像ごとに評価（1〜5星など）を付与できる
- 「良い」「保留」「不要」などの状態を持てる
- 評価や状態を基に一覧の並び替えができる
- 必要に応じてハッシュ管理で重複画像の検出ができる

## 画面構成

### メイン画面
- 左側: フォルダ・タグ一覧
- 中央: 画像サムネイル一覧
- 右側: 画像情報・メタデータ・タグ編集
- 上部: 検索バー、ソート、並び替え、フィルタ

### 画像詳細画面
- 大きな画像表示
- タグ一覧
- 評価
- 追加メモ
- 画像の前後移動
- 関連画像表示

### 画像整理画面
- 対象画像の一括選択
- タグ追加・削除
- 移動先フォルダ選択
- 確認ダイアログ

## 操作フロー

### 典型的な利用フロー
1. 画像フォルダを読み込む
2. 自動で画像一覧を表示する
3. 画像にタグを付与する
4. 検索バーまたはタグ一覧で条件を絞る
5. 評価や状態を付与する
6. 画像を整理して一つのライブラリとして使う

### 典型的な整理フロー
1. 画像を選択
2. 複数タグを付与
3. 画像を移動または分類
4. 同じタグの画像をまとめてレビュー
5. 使う画像だけ残し、不要画像を削除または非表示化

## 非機能要件
- 大量画像でもある程度高速に動作する
- 画像サムネイルのキャッシュを使う
- タグ・評価・検索のデータが失われないように永続化する
- 参照先の画像が削除された時も安全に扱える
- システムが利用できない環境では、判定メッセージを明確に表示する
- GUI が実行できない環境ではクラッシュせず、説明を出す

## 重要な設計方針
- フォルダ構造を「正規の保存先」ではなく「参照の一部」として扱う
- タグは一番重要な整理軸にする
- 画像ファイルの物理配置と、メタデータ管理を分離する
- 画像編集機能よりも「整理・検索・再利用」の体験を優先する
- 便利さと安全性を両立するため、批量処理には確認ダイアログを入れる

## 期待するユーザー価値
- 画像を探す時間が減る
- フォルダを縦横無尽蔵に作る必要がなくなる
- タグで見たい視点を自由に切り替えられる
- 作品や素材の再利用がしやすくなる
- 一貫した整理が可能になる

## 実装指針
- Python + Tkinter ベースで実装可能な構成を優先する
- タグ管理はローカル JSON / CSV / SQLite で保存可能な構成にする
- 画像表示は Pillow を使い、サムネイル生成をキャッシュする
- トラブル時はログを残し、例外時のユーザー表示を簡潔にする
- GUI 環境チェックを明示し、Linux のヘッドレス実行時には適切に失敗する

## 受け入れ基準
- 画像を選択してタグを付与できる
- 同じタグを持つファイルが一覧で絞り込める
- タグ付き画像を一括で移動または整理できる
- 複数の画像を比較しやすい表示ができる
- タグの編集、削除、作成ができる
- 無効な画像や空値が来てもクラッシュしない
- GUI が使えない環境では、分かりやすいメッセージが出る

## 生成AIへの指示文

以下の文章をそのまま設計支援のプロンプトとして使う:

> あなたは画像管理アプリの設計アドバイザーです。画像ファイルをタグで整理し、検索・選別・分類・整理できるアプリを設計してください。アプリは画像ビューアでありながら、画像をメタデータベースと連携して管理する設計にしてください。タグは複数付与可能、検索は AND/OR/除外ができ、画像状態や評価と連携できること。大量の画像を扱えるようにサムネイル、キャッシュ、UIレイアウトを考慮し、GUIが利用できない環境では明確な失敗メッセージを出すこと。設計は、ユーザーの整理体験を優先し、ローカルファイルの安全な管理と可視性を担保するものにしてください。

## まとめ
この設計プロンプトでは、「画像をただ見る」ためのアプリではなく、「画像を管理するためのアプリ」としての理想像を定義している。中心はタグ管理であり、ファイル整理・検索・再利用までを一貫して扱えるようにすることが要件である。
